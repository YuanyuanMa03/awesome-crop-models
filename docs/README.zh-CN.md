# Awesome Crop Models：作物与农业过程模型清单

收录GitHub上公开的作物模型，以及土壤、水分、气象、病虫害等农业与环境过程模型，按“**模拟的作物或农业过程 → 编程语言 → 仓库**”的树状结构浏览。

[查看完整清单](../README.md) · [待审队列](discovered.md) · [运行状态](status.md) · [竞品与参考](competitor-landscape.md)

## 怎么浏览

- 第一层是作物或过程，第二层是编程语言，同一语言内按GitHub star排序。
- 每个仓库只出现一次：挂在它最主要的作物或过程下，归入它的主要编程语言。语言默认取GitHub主语言，`Jupyter Notebook`记为Python、`FORTRAN`记为Fortran；主语言明显误导时可在种子记录里人工指定。
- 主页[README](../README.md)直接列出作物模型，并给出所有分支的目录。其他类型各有独立页面：
  - [过程模型](process-models.md)
  - [框架与工具](tools.md)
  - [应用与案例](applications.md)
  - [数据驱动模型](data-driven.md)
- GitHub只显示README的前500 KiB，因此每页正文控制在约400 KB以内，超出部分自动续到编号页（如`data-driven-2.md`），目录链接直接指向条目所在页。

## 收录范围

每个条目属于以下四类之一：

- **模型（model）**：过程模型，包括通用或多作物模型、单一作物模型，以及物候、光合、植株结构、根系、土壤水热、碳氮养分、蒸散与灌溉、水文侵蚀、气象、病虫害、温室气体等过程模型。重新实现、移植版、教学版和已归档代码都算。
- **工具（tool）**：建模框架、模型接口与封装、率定/敏感性/不确定性分析、数据同化与遥感、区域与格点模拟、输入参数与数据、教程。
- **应用（application）**：把模型用于某项研究、某个地区或某个分析的仓库，如模拟设置、情景运行和分析代码。
- **数据驱动（data-driven）**：用统计或机器学习方法预测作物变量（产量、生物量、物候、需水）或农业过程（土壤水分、蒸散、养分）的模型。

不收录：图像识别（病害、杂草、果实检测）、作物或肥料推荐、价格预测、IoT与传感器面板、农场管理或电商应用、与作物过程模型无关的通用数据处理，以及普通fork和镜像。有实质独立开发的fork可以收录；原仓库不在GitHub上时，CRAN只读镜像也可代表该软件包（如`cran/chillR`）。

第一层分类：

- 作物：通用与多作物、水稻、小麦、玉米、大麦高粱谷子等其他谷物、大豆、其他豆类与油料、马铃薯、木薯等根茎类、棉花、甘蔗与甜菜、蔬菜、果树与葡萄、油棕咖啡可可等种植园作物、草地牧草与饲草、生物能源及其他作物。
- 过程：物候与发育、光合冠层与蒸腾、植株结构与FSPM、根系与根际、土壤水热、土壤碳氮与养分、农业温室气体、蒸散与灌溉、天气与农业气候、病虫草害、水文侵蚀与流域、陆面与全球植被、温室与可控环境。
- 工具：框架与平台、接口与封装、率定敏感性与不确定性、数据同化与遥感、区域与格点模拟、输入参数与数据、教程与教学。

只对单一作物有效的过程模型归入该作物，通用的过程模型归入相应过程。

## 当前覆盖情况（2026-10-23）

- **已收录15,292个仓库**：过程模型2,113个（作物模型438个、过程模型1,675个），框架与工具1,584个，应用769个，数据驱动模型10,826个。
- **共筛查106,974个仓库**：收录15,292个，排除78,835个（每个都记录理由），未收录的fork 795个，待审12,052个。
- **发现途径**：
  - 525条仓库检索，覆盖模型名称、过程术语、作物名、多种语言和topic，按创建时间切片绕过单次检索1,000条上限，全历史检索已完成一轮。
  - 枚举33个模型维护机构和作者账号的全部公开仓库。
  - 做过一次代码检索，例如`import pcse`和DSSAT文件扩展名，共找到142个仅凭代码检索发现的入选仓库，来源字段记为`code:`。
- **审核方法**：
  - 先用可复核的规则批量排除明显噪声，如图像处理、推荐系统、IoT、游戏、价格预测和名称撞车。
  - 再按信号强弱逐批人工审查。
  - 最后复查了自动排除中带强模型信号的473个仓库，找回约70个被误排的模型，如`TimHessels/SEBAL`、`jvdkwast/PySEBS`、`DrylandEcology/SOILWAT2`。
- **已知缺口**：
  - 待审的12,052个候选多为低星、描述很少的仓库。随机抽查150个，明确相关的只有约1–2%，另有约4%是学生级产量预测项目，尚未逐一审完。
  - 全历史检索记录了28个覆盖缺口：结果总数变化10个，结果不完整9个，页数少于报告总数8个，跨页重复1个。近30天检索通道还有394个待查任务，交给每日任务继续。
  - 描述极少的仓库可能检索不到，所以本项目不声称完全覆盖。

## 数据文件

| 文件 | 内容 |
|---|---|
| `config/seeds.json` | 收录记录：`github_id`、类型、主题，可选语言和描述覆盖 |
| `config/excluded.json` | 排除记录：仓库ID → 仓库名与理由 |
| `catalog/repositories.json` | 已收录和待审仓库的公开元数据 |
| `config/queries.json`、`config/owners.json` | 检索式与维护者账号 |
| `state/` | 检索断点、元数据轮换刷新与运行健康记录 |

被排除的仓库只保留在`config/excluded.json`，每次更新都会把它们从`catalog/repositories.json`和检索来源记录中删掉。这样目录文件约29 MB，低于GitHub对单个文件50 MB警告、100 MB拒收的限制。

语言取自GitHub的代码语言统计，可能包含辅助脚本。源码公开不等于所有文件都能按开源许可复用；NOASSERTION、未知或自定义许可会保留待核标记。

## 运行

需要Python 3.11或以上，运行时没有第三方依赖，也不调用付费模型。

```bash
python scripts/catalog.py validate
python scripts/catalog.py update --max-requests 160 --discovery-pages 80 --refresh-limit 40
python scripts/catalog.py render
PYTHONPATH=src python -m unittest discover -s tests -v
```

认证通过环境变量`GH_TOKEN`或`GITHUB_TOKEN`，不要写进仓库。未配置时只能匿名运行，配额较小。每次运行有请求预算和超时；预算用完会保存部分进度，失败时保留上次健康时间和已有目录。

新候选出现在[待审队列](discovered.md)：要收录，就在`config/seeds.json`里加记录；要排除，就在`config/excluded.json`里写明理由。主题与字段说明见[贡献指南](../CONTRIBUTING.md)。

GitHub Actions工作流计划每天UTC 03:17运行，也可手动触发。它在同一次运行里采集、校验、生成页面，并提交限定的数据和状态文件，不依赖个人电脑。本地源码只包含工作流定义，发布后才会真正启用在线调度，届时需要确认。

## 作者离开后如何继续运行

检索式、种子、排除记录、仓库身份和断点都保存在普通JSON文件中，任何维护者都可以接手或fork。建议由有多位维护者的组织持有，并按[维护交接说明](MAINTENANCE.md)记录定时任务和恢复方式。

GitHub可能延迟任务，长期无活动的公共仓库还会被停用定时工作流；账号、权限和平台政策也可能变化。所以本项目能减少对个人的日常依赖、暴露故障并方便恢复，但不能保证基础设施永不停止。每次真实检查都会记录状态：零新增就记为零，失败不会改写成成功。

“覆盖GitHub上所有相关开源仓库”是持续追求的目标。可以验证的是具体的检索范围、时间窗口、已完成的页和尚未解决的缺口，而不是全站覆盖率。本项目只整理公开来源和采集框架；阅读科学公式、独立审核和制作benchmark另行开展。
